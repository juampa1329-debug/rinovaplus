2026-10-20. Implementación en la misma carpeta y runtime local `http://127.0.0.1:4173`. Se conserva Glass, Inbox, catálogo y proveedores existentes. Sin copias de proyecto, worktrees, tests automatizados, lint, typecheck, build, commit, publicación ni túneles. La política automática permanece desactivada. El corte inicial no hizo llamadas a modelos; la ampliación manual Gemini/ElevenLabs autorizada posteriormente se describe al final.

## Superficies implementadas

- **Ajustes → IA → Asistente de admisiones · OpenRouter:** modelo principal/respaldo, temperatura, tokens, instrucción institucional y activación explícita. Esta política del Inbox es independiente del banco Asistente existente: no reemplaza Gemini/ElevenLabs. La clave se guarda mediante el propietario existente Ajustes → APIs; AES-256-GCM, nonce aleatorio y AAD, llave fuera de SQL. No hay segunda bóveda.
- **Conocimiento:** cargar PDF/TXT como borrador, revisar fragmentos paginados, confirmar fuente oficial y publicar, retirar de respuestas, eliminar y buscar contexto. El catálogo SIIE existente permanece accesible debajo. Nunca se publica automáticamente un archivo.
- **Memoria del aspirante:** conversaciones SQL existentes, datos declarados con cita y mensaje de origen, consulta/reinicio con revisión y generación; el chat se conserva. Se puede revisar el prompt ensamblado sin llamar a IA, incluso bajo control humano.

## Cliente y ensamblador solicitados

`backend/app/modules/ai/infrastructure/openrouter.py`: `OpenRouterClient.complete`. URL fija `https://openrouter.ai/api/v1/chat/completions`, Bearer y atribución `HTTP-Referer`, `X-Title`, `X-OpenRouter-Title`. Máximo tres intentos y plazo total de 40 segundos; backoff exponencial con jitter, `Retry-After` numérico/fecha respetado dentro del plazo. Transitorios 408/429/500/502/503/504/529; 401/403/402 ordinario no se reintentan. Los errores estructurados dentro de HTTP 200 también se procesan. Timeout/lectura incierta de un POST no se reenvía automáticamente. Sin redirecciones, proxy de ambiente, herramientas ni SDK adicional. `models: [principal, respaldo]` usa fallback nativo; no multiplica el bucle del banco sintético. Guarda modelo real y uso saneado, nunca clave, cuerpo bruto de error ni prompts en logs. Respuestas incompletas, filtradas, negativas o JSON inválido no se envían al aspirante.

`backend/app/modules/ai/application/admissions_prompt.py`: `assemble_prompt`. Ensambla seguridad institucional e instrucción del operador, fuentes publicadas con UUID/documento/página, memoria declarada y hasta 12 mensajes externos confirmados; termina con el mensaje actual una sola vez. Las notas locales internas y envíos fallidos/no confirmados quedan excluidos. El worker conserva el ID del mensaje actual como metadato para evidencias de memoria. Máximo 40.000 caracteres de contexto; la salida es JSON validado por `validate_reply`. Las referencias deben pertenecer exactamente al contexto recuperado. Las citas válidas evitan referencias inventadas, pero no certifican por sí solas exactitud factual; requiere evaluación con documentos reales.

## SQL, recuperación y control humano

Migración explícita **017**, `backend/tools/migrate_ai_admissions.py`: seis tablas nuevas en `crm_ai`: `AdmissionsPolicy`, `KnowledgeDocument`, `KnowledgeChunk`, `KnowledgeTerm`, `ProspectMemory`, `ResponseJob`. Todos los JSON son `NVARCHAR(MAX)` con `ISJSON`. Sólo expansión; no altera tablas core ni sus datos, no crea tablas al arrancar. Modo `local_sql_copy`, TLS y `verify_target` antes/después; transacción con rollback. La reversión funcional es desactivar política y retirar documentos; no se ejecutó DDL destructivo.

La recuperación es **léxica SQL mediante índice invertido de términos**, normalización de tildes y ranking de coincidencias/frecuencia; no `LIKE` masivo, embeddings, vector o búsqueda semántica simulada. Devuelve hasta cinco fragmentos publicados; sin coincidencias no incorpora textos ajenos y deriva al asesor.

PDF: política estructural contra contenido activo reutilizada del Inbox y extracción en subprocess acotado: 5 MB, hasta 150 páginas, 300.000 caracteres, 250 fragmentos, 512 MB y timeout de diez segundos. TXT UTF-8. El PDF sin texto exige versión textual/OCR separado; no se finge lectura de un escaneo. Segmentación hasta 1.600 caracteres con solapamiento 120, página y SHA del original. SQL conserva texto/procedencia, no una copia descargable del archivo original. Máximo cien documentos activos; consulta/revisión paginadas.

Los trabajos se insertan **en la misma transacción de ingesta externa** sólo cuando ya estaba activa la política y la conversación estaba en control IA. No se recorren chats históricos al activar o devolver el control al bot. El worker independiente genera fuera de HTTP y mantiene lease, deduplicación por mensaje y recuperación acotada. Una entrada posterior vuelve obsoleto el trabajo anterior.

Antes de inferir, entre reintentos y antes de confirmar se revisan política, configuración global, credenciales, revisión documental, generación/revisión de memoria, identidad/cuenta exactas, epoch/control, ventana del canal y secuencia del diálogo. Mensaje, `outbound_queue` y `MessageRoute(origin=bot)` se confirman juntos. El despachador vuelve a comprobar la frontera persistida antes del POST. El control humano y la invalidación por reset/configuración/documentos impiden envíos pendientes obsoletos. Un POST ya iniciado no se puede revocar.

Solicitud humana, falta de conocimiento, entrada multimedia sin texto interpretable o fallo del proveedor transfieren a control humano, prioridad alta (conserva urgente) y tarea SQL vinculada al asesor asignado, visible en el mini CRM. No se envían emails ni notificaciones externas. No se confirma inscripción/pago por LLM: `registration_reported` es sólo declaración con evidencia literal. El reinicio incrementa generación y watermark para impedir que el historial borrado regenere la memoria inmediatamente.

## API real

Todas las rutas requieren guard local existente (loopback, host/origen admitidos, `X-CRM-Local: 1`); esto no equivale a autenticación/RBAC.

- `GET/PUT /api/v1/ai/settings`; `PUT /api/v1/ai/settings/openrouter-key` reutiliza bóveda y revisión existentes.
- `GET /api/v1/ai/knowledge`; `PUT /knowledge/{uuid}/content?filename=...&title=...`, binario `application/octet-stream`, hasta 5 MB e idempotencia UUID/hash.
- `GET /knowledge/{uuid}/chunks?offset=...`; `PUT /knowledge/{uuid}` con revisión, estado y confirmación oficial al publicar; `GET /knowledge/search?q=...`.
- `GET /api/v1/ai/conversations`; `GET/DELETE /conversations/{uuid}/memory`; `POST /conversations/{uuid}/context-reset`, revisión obligatoria.
- `POST /conversations/{uuid}/context`, sólo ensamblado sin red; `GET /api/v1/ai/jobs`, estados/modelo/error saneados.
